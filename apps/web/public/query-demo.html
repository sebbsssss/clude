How grounding works
The data lives in Clude, not in a live query
Clude consumes Solana on-chain data from Google BigQuery into its local memory, then answers by traversing that memory locally. No live BigQuery query, no RPC call at answer time.

Same model. Same question.
Clude is the only variable.

This is an apples-to-apples test. Both columns are the exact same model (Claude Haiku 4.5) answering the exact same question. The only difference is whether Clude's memory layer retrieved the fact and put it in context. With Clude, the model answers precisely and you can verify it on Solscan. Without it, the model has no way to know a specific historical on-chain value, so it either declines (honest) or guesses (a hallucination). Clude is what turns "can't answer" into "answers correctly."

How Clude does it
1 Ingest
Store the data as memory
Solana on-chain facts from Google BigQuery are written into Clude's memory once, each as a typed, embedded memory. No live query at answer time.
2 Recall
Retrieve the relevant fact
At question time, Clude runs hybrid vector + keyword recall over its memory and surfaces the few memories that actually answer the question.
3 Ground
Answer only from what it found
The recalled fact goes into the model's context. It answers from that, or says "I don't know" if recall came back empty. It never guesses.
The right-hand column is that same model with step 2 removed: no memory, no retrieved fact. That is the honest comparison. Not "Clude has a database and the model doesn't," but "the memory layer either found the fact or it didn't."

03
The data & method

Machine-checkable answers from a frozen public dataset. No cherry-picking, no adjustable ground truth.

Dataset
bigquery-public-data.crypto_solana_mainnet_us
Snapshot frozen 2025-03-31. Immutable ground truth. Tables: Blocks, Transactions, Accounts, Tokens.
Model
claude-haiku-4-5
Same model, same system prompt. Only difference is Clude's recalled memories in context. No fine-tuning. No prompt engineering advantage.
Ground truth
Exact values from BigQuery: slot numbers, block times (UTC), validator pubkeys, transaction counts. Answers are string-matched, not LLM-judged.

Solana data on BigQuery ↗
Scoring rule
Abstaining ("I don't know" / "not enough information") counts as not hallucinating. It is the correct behavior when memory is absent. Hallucination = confident wrong answer. Clude is optimised for grounded-or-abstain, not for guessing.
"Same model, with vs without Clude's memory. Abstaining counts as not hallucinating. The goal is grounded-or-abstain, never fabricate."
